# Birhan — iOS build & release

The app is one Expo (SDK 57) codebase; iOS shares all of `src/`. Everything that
can be prepared on Linux is done and committed. The remaining steps —
compiling the native project and signing — **require macOS + Xcode** (or EAS
Build's cloud macOS) and cannot run on Linux.

## What's already set up (in the repo)

- `app.json` → `expo.ios`: bundle id **`online.birhan.app`**, `buildNumber` "1",
  `supportsTablet`, and `ITSAppUsesNonExemptEncryption: false` (skips the App
  Store export-compliance prompt — the app uses only standard HTTPS).
- The Android-only **APK self-updater is hidden on iOS** (Settings → Updates).
  iOS cannot sideload and the App Store rejects self-updaters, so on iOS updates
  come through the App Store. Guarded with `Platform.OS !== 'ios'`; Android is
  unchanged.
- `eas.json`: a `preview` profile builds an **iOS Simulator** app (no Apple
  account needed) and `production` auto-increments the build number.
- Verified on Linux: the iOS JS bundle exports cleanly (`expo export --platform
  ios`) — the whole JS layer, including the bundled `bible_v4.db`, is iOS-clean.
- `ios/` is git-ignored and regenerated by prebuild, exactly like `android/`.

`android/` was never touched making any of this.

## Build it on a Mac (free — your own iPhone)

Testing on your own device needs only a **free Apple ID** (7-day signing); the
$99/yr Apple Developer Program is only for TestFlight / the App Store.

```bash
# from the repo root, on macOS with Xcode + CocoaPods installed
npx expo prebuild --platform ios        # regenerates ios/ from app.json
cd ios && pod install && cd ..           # installs native pods (macOS only)
open ios/birhan.xcworkspace              # NOT the .xcodeproj — use the workspace
```
In Xcode: select the `birhan` target → **Signing & Capabilities** → check
*Automatically manage signing* → pick your personal Apple ID team. Plug in your
iPhone, select it as the run destination, press **Run**. First run: on the phone,
Settings → General → VPN & Device Management → trust your developer cert.

## Or build in the cloud with EAS

Needs an Expo account (`eas login`); a device/App-Store build also needs an
Apple Developer membership, which EAS will walk you through for credentials.

```bash
eas build --platform ios --profile preview      # Simulator .app, no Apple acct
eas build --platform ios --profile production    # signed device/store build
eas submit --platform ios                        # upload to App Store Connect
```

## Notes / still open

- **Push notifications (announcements)** are dormant on iOS for the same reason
  as Android: they need APNs credentials wired to the Expo project (the iOS
  equivalent of FCM). The **daily-verse reminder is a local notification** and
  works on iOS with no extra setup.
- Set a real **CFBundleDisplayName** if you want the home-screen label to differ
  from `birhan`.
- When you cut an iOS release, bump `expo.ios.buildNumber` (or let EAS
  auto-increment) the way `versionCode` is bumped for Android.
